# Архитектура Bazar

## Как я разделил проект

```text
apps/api, apps/cli
        |
        +-- bazar_data: база данных, таблицы и загрузка ESCI
        +-- rank_system/retrieval: BM25
        +-- rank_system/two_tower: обучение двухбашенной модели
        +-- rank_system/serving: загрузка активной модели и поиск
```

Я отделил работу с данными и моделями от HTTP API. Благодаря этому модели можно обучать и проверять без запуска сервера.

## Как проходят данные

1. Команда `ingest-esci` читает два файла ESCI и выбирает стабильный набор запросов.
2. Я проверяю данные, очищаю текст и перевожу метки `E`, `S`, `C`, `I` в оценки `3`, `2`, `1`, `0`.
3. Товары записываются в `products`, запросы в `queries`, а связи между ними в `relevance_judgments`.
4. По каталогу я строю индекс BM25.
5. На обучающей части данных я обучаю двухбашенную модель.
6. Обе модели я проверяю на одной и той же тестовой части.
7. Лучшую модель сохраняю в таблице `model_versions` как активную.
8. API загружает активную модель и использует её в `/search`.

## Где хранятся товары

За один запуск я использую только одну базу данных:

- SQLite для локального запуска, обычно `data/prod/bazar.db`;
- PostgreSQL для запуска через Docker Compose.

Адрес задаётся параметром `--database-url` или переменной `DATABASE_URL`. SQLAlchemy позволяет использовать одинаковые таблицы и запросы в обоих вариантах. Данные не копируются между SQLite и PostgreSQL автоматически.

## Таблицы

| Таблица | Что я в ней храню |
| --- | --- |
| `products` | карточки товаров и текст для поиска |
| `queries` | поисковые запросы и исходное разбиение данных |
| `relevance_judgments` | оценки релевантности товара запросу |
| `model_versions` | версии моделей, метрики и путь к файлам |
| `search_events` | просмотры, клики, добавления в корзину и покупки |

## Модели

### BM25

Я сохраняю индекс BM25 в JSON. Если оценки совпадают, сортирую товары по `product_id`, поэтому результат можно повторить.

### Двухбашенная модель

Я отдельно обучаю векторы запросов и товаров. Модель усредняет векторы токенов, нормализует результат и учится отличать подходящие товары от остальных товаров в пакете.

## Воспроизводимость

- я всегда выбираю запросы в одном порядке;
- использую готовое разделение ESCI на обучение и тест;
- сохраняю случайное зерно обучения и хеш данных;
- записываю параметры и метрики в MLflow;
- не добавляю файлы моделей и индексов в Git, потому что их можно пересобрать командой `bazar run-demo`.
