# Bazar - поиск и ранжирование товаров

Bazar - мой проект по поиску и ранжированию товаров. Я использовал публичный набор данных [Amazon Shopping Queries (ESCI)](https://github.com/amazon-science/esci-data) и собрал рабочий путь от загрузки данных до поиска через API. Проект пока находится в разработке.

## Бизнес-задача

Я решал задачу запуска MVP поиска по каталогу: выбрать модель с лучшим качеством выдачи при p95 менее 100 мс, подключить её к API и подготовить сбор поисковых событий.

Порог 100 мс я использую как начальный технический бюджет для этапа поиска, а не как подтверждённый бизнесом норматив. Он оставляет время на обработку запроса в API, обращение к хранилищу, передачу данных и отображение результатов. Для реального продукта этот порог нужно уточнять по нагрузочным тестам и пользовательским метрикам.

Я не заявляю рост CTR или конверсии: для такого вывода нужны реальные события и A/B-тест. Текущий результат - работающий MVP и обоснованный выбор модели на публичной разметке.

## Что я сделал

- загрузил товары, запросы и оценки релевантности из ESCI;
- добавил проверку данных, удаление дублей и хеш набора данных;
- реализовал поиск с помощью BM25;
- реализовал двухбашенную модель на NumPy;
- добавил общую оценку моделей по NDCG@10, MRR@10, Recall@10/50/100 и времени ответа;
- сделал правило, которое выбирает лучшую модель по качеству и скорости;
- добавил реестр версий моделей и запись экспериментов в MLflow;
- реализовал API для поиска, записи событий и просмотра активной модели;
- добавил запуск через Docker Compose и тесты основного сценария.

## Результаты

Для контрольного прогона я взял 2 000 запросов из `small_version=1` для локали `us`. После загрузки в базе оказалось 37 971 уникальный товар и 39 753 оценки релевантности. Для проверки моделей я использовал 606 тестовых запросов с положительными метками.

| Модель | NDCG@10 | MRR@10 | Recall@10 | Recall@50 | Recall@100 | p50, мс | p95, мс |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| BM25 | **0,509** | **0,762** | **0,889** | **0,941** | **0,960** | 34,22 | 69,27 |
| Двухбашенная | 0,196 | 0,411 | 0,584 | 0,726 | 0,771 | **17,30** | **18,75** |

Двухбашенная модель работает быстрее, но заметно уступает BM25 по качеству. BM25 показал p95 69,27 мс и уложился в выбранный бюджет 100 мс, поэтому для MVP я выбрал именно его. Пользовательский запрос обрабатывается через API, а действия с результатами сохраняются для будущего обучения. Подробности записал в [docs/MODEL_DECISION.md](docs/MODEL_DECISION.md).

## Куда загружаются товары

За один запуск я использую только одну базу данных. Нужную базу задаю через `--database-url`, а для API через переменную `DATABASE_URL`.

- Для локального запуска я использую SQLite. По умолчанию это файл `data/prod/bazar.db` внутри проекта.
- Для запуска через Docker Compose я использую PostgreSQL по адресу `postgresql+psycopg://bazar:bazar_dev_only@localhost:5432/bazar`.

В обоих случаях товары попадают в таблицу `products`, запросы в `queries`, а оценки релевантности в `relevance_judgments`. Данные не записываются сразу в две базы. Команда подготовки моделей и API должны использовать один и тот же адрес базы.

## Как устроен проект

```text
Amazon ESCI parquet
        |
        v
загрузка и проверка ---> SQLite или PostgreSQL
        |                         |
        +-> индекс BM25           +-> товары / запросы / разметка
        +-> двухбашенная модель   +-> версии моделей / события
                  |
                  v
        сравнение моделей ---> активная модель ---> FastAPI
```

Каталог, разметку и события я храню в выбранной базе. Индексы и файлы моделей сохраняю отдельно, потому что их можно пересобрать. Более подробное описание есть в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) и [docs/DATA_CARD.md](docs/DATA_CARD.md).

## Быстрый запуск с SQLite

Для запуска нужны Python 3.11+ и [uv](https://docs.astral.sh/uv/). Сначала нужно скачать из официального репозитория ESCI два файла:

- `shopping_queries_dataset_examples.parquet`;
- `shopping_queries_dataset_products.parquet`.

Их нужно положить в `data/raw/esci/`, а затем выполнить:

```bash
uv sync
uv run bazar run-demo \
  --database-url data/prod/bazar.db \
  --examples data/raw/esci/shopping_queries_dataset_examples.parquet \
  --products data/raw/esci/shopping_queries_dataset_products.parquet \
  --output-dir artifacts/release \
  --model-version esci-release-v1 \
  --max-queries 2000 \
  --epochs 20
```

Эта команда создаёт файл `data/prod/bazar.db`, загружает туда данные, строит BM25, обучает двухбашенную модель, сравнивает модели и сохраняет выбранную версию.

API нужно запустить с той же базой:

```bash
DATABASE_URL=data/prod/bazar.db uv run uvicorn apps.api.main:app --reload
```

Примеры запросов:

```bash
curl 'http://127.0.0.1:8000/search?q=wireless+headphones&limit=5'
curl 'http://127.0.0.1:8000/models/active'
```

Документация API будет доступна на `http://127.0.0.1:8000/docs`.

## Запуск с PostgreSQL

```bash
cp .env.example .env
docker compose up -d db
uv run bazar run-demo \
  --database-url postgresql+psycopg://bazar:bazar_dev_only@localhost:5432/bazar \
  --examples data/raw/esci/shopping_queries_dataset_examples.parquet \
  --products data/raw/esci/shopping_queries_dataset_products.parquet \
  --output-dir artifacts/release \
  --model-version esci-release-v1 \
  --max-queries 2000 \
  --epochs 20
docker compose up --build api
```

В этом варианте я храню каталог и реестр моделей в PostgreSQL. Каталог `artifacts/` с индексами и моделями подключается к контейнеру API только для чтения.

## Ограничения

- Я проверял модели на публичной разметке, поэтому результаты не показывают рост CTR, конверсии или выручки.
- Время ответа я измерял на одном локальном процессоре. На другом оборудовании оно будет отличаться.
- Двухбашенную модель я сделал как простую и понятную реализацию на усреднённых векторах токенов. В ней пока нет предобученной трансформерной модели и быстрого приближённого поиска.
- События из демонстрационного API я помечаю как смоделированные и не смешиваю с разметкой ESCI.
- Динамическое ценообразование и рекомендации я оставил для следующих этапов проекта.
